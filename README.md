# 衣装簡単切替ツール

VRChatアバターの衣装を、個別またはグループで切り替えるUnityエディター拡張です。Radial Inventory System V4 4.6.0を基にした改変版です。

**[配布ページ・VCCに追加](https://l1zerox.github.io/wardrobe-switch-tool/)**

VCC登録URL：`https://l1zerox.github.io/wardrobe-switch-tool/index.json`

## 主な機能

- プロップの合体と分離、初期衣装の選択、衣装の親名からのグループ名入力。

- Expressionsメニューから、個別切替・まとめて着る・まとめて脱ぐを操作。
- 着替え時に他の登録衣装を自動OFF。アクセサリーなどのグループは保持可能。
- 衣装だけの透過PNGと、グループごとに着替えた全身PNGを自動／手動で撮影。
- 多数のメニュー項目を自動でページ分割。再生成時もメニューの参照を保持。
- 元のSimple／Basic／Advancedの編集画面、設定JSON、排他設定やセットを継承。

アバターや衣装モデル、購入素材、個人の設定・サムネイルは付属しません。

**元のRadial Inventoryを別途インストールする必要はありません。** 必要な機能は本パッケージに含まれています。VRChat Avatars SDKとUnityの依存パッケージは必要です。既存設定を保つため、内部クラス名やデータ保存先には従来の名称を残しています。

## 実験：靴とヒール補正を連動（1.11.0）

「基本」「詳細」モードで利用できます。既存のアバターへの影響を避けるため、更新直後はOFFです。

1. 上部の **実験：靴とヒール補正を連動** をONにします。
2. 靴のプロップを選択し、詳細の **実験：ヒール補正** を確認します。
3. **自動** では、プロップ名または対象オブジェクトの名前に `Shoes` が含まれるものを、大文字・小文字を区別せず検出します。Body_all／bodyallを優先し、Bodyなどのメッシュも候補にします。`high heels`、`High_Heels`、`ハイヒール`などを認識します。
4. **履いたとき** を0〜100で設定します（初期値100、数値入力・小数可）。脱いだときは0です。
5. 名前が異なる場合や候補が複数ある場合は **手動指定** に切り替え、アバター内の **対象メッシュ** と **ブレンドシェイプ** を選びます。連動不要の靴は **OFF** にできます。
6. **適用する** → シーンを保存 → アバターを再アップロードしてください。Expressionsの既存の個別着脱／まとめて着る・脱ぐから連動します。

他のグループの靴に着替えたときは、その靴の設定値に切り替わります。個別に脱いだ状態を記憶している場合は、元の衣装に戻っても靴を脱いだ状態なら0になります。同じメッシュ・シェイプを操作する靴が同時にONの場合は最大値を使います。合体したプロップは元の靴の設定を引き継ぎ、分離すると元の設定に戻ります。異なる補正先の靴を合体した場合は手動指定が必要です。

候補不明・複数候補・存在しない参照・範囲外の値・既存FXによる同じ補正の操作を見つけた場合は、生成前に理由を表示します。その靴を手動設定するかOFFにしてください。元のアバターのブレンドシェイプ値を直接書き換えず、生成FXで制御します。全体をOFFにして再適用すると、この機能の生成レイヤーと内部パラメーターを除去します。

実験版は、オブジェクトのON/OFFで切り替える衣装が対象です。独自の着脱アニメーション・マテリアル差替えを使う衣装は対象外です。既存FXと衣装アニメーションの競合を検査しますが、ビルド時に他ツールが合成する補正まで網羅するものではありません。もちふぃったーなどで変換した衣装も値を調整できますが、衣装の形状・ボーン・接地位置自体を修正する機能ではありません。

Unity 2022.3.22f1 / Avatars SDK 3.10.3で生成・保存と遷移条件を検証済み。VRChat実機での着用・他ツールのビルド時合成後の挙動は別途確認が必要です。

## 合体前のプレビュー（1.10.0）

「プロップを合体…」でパーツにチェックを入れると、右側のプレビューが自動更新されます。1個だけ選んだ状態でも確認できます。合体は2個以上選んでから実行してください。

- **衣装だけ**：チェックしたパーツだけを表示。アバター本体・髪・他の登録衣装は表示しません。
- **アバター全体**：本体とチェックしたパーツを表示。他の登録プロップは非表示にします。ツールに未登録の本体・髪などは現在の表示状態を使います。
- **小・中・大**：プレビュー枠を128／256／384pxに変更。ウィンドウが小さいときは右欄をスクロールできます。
- **向き・ズーム**：見たい角度や拡大率へ調整。「プレビューを更新」でHierarchy等の変更も再取得できます。

透過部分は市松模様で表示します。プレビューは一時的な画像で、既存のサムネイル・PNG・初期状態や元のアバターは変更しません。プレビューの角度・大きさ・表示モードは合体ウィンドウ内の表示設定です。サムネイルに反映する設定ではありません。

## プロップの合体・初期衣装（1.9.0）

「基本」「詳細」のグループ設定で **プロップを合体…** を押し、まとめたいパーツを2個以上選択します。名前を入力して合体すると、Expressionsでもひとつのスイッチで全対象を切り替えます。合体した行を選んで **分離する** を押すと、元の名前・画像・個別設定へ戻せます。設定JSONの保存・再読込後も分離できます。

モデルやメッシュは加工せず、ツールの登録だけをまとめます。独自アニメーション・マテリアル・タイマー・ボーン追従・独自パラメーター・セット操作があるプロップは合体できません。ローカル動作・保存・排他グループは同じ設定同士を選んでください。合体中に変更した個別設定は、分離すると合体前の値へ戻ります。ただし以下の初期衣装設定は優先されます。

画面上部の **初期衣装** から最初に着るグループを選びます。選んだグループ内だけ「初期状態」がONとなり、他グループはOFFになります。後から追加したプロップにも適用します。「なし（すべてOFF）」も選べます。初期衣装を使っている間はプロップの「有効状態を保存」を一時的に無効化し、アバター再読み込み時に前回の状態より初期衣装を優先します。「個別の初期状態を使う」に戻すと保存設定が復帰し、初期チェックは個別編集できます。元の初期チェックの組み合わせを自動復元する機能ではありません。

排他設定のあるグループを初期衣装にする場合は「グループ内の排他を解除」をONにしてください。グループ間の着脱記憶は引き続き利用できます。

衣装の親を「衣装を追加」へ登録すると、空のグループや「グループ0」等の標準名には、アバター直下の衣装の親名が自動で入ります。自分で付けた既存名は保持します。既存グループを変更する場合は **衣装の親名に合わせる** を押します。複数の親にまたがるグループには名前を推測しません。

変更後は **適用する → シーンを保存 → アバターを再アップロード** してください。

## 対応環境

Unity 2022.3 / VRChat Avatars SDK **3.10.3以上・3.11.0未満**。
バックアップ付き移行ランチャーはWindows PowerShell 5.1用です。Macでの動作は未検証です。

## VCCから導入

1. 配布サイトの「VCCに追加」を押して、VCCで登録を確認します。
2. 対象プロジェクトの「Manage Project」を開き、「衣装簡単切替ツール」を追加します。
3. Unityを開き、上部の **衣装簡単切替ツール → エディター** を選びます。
4. アバターと衣装を設定し、「適用する」を押して、シーンを保存します。

ボタンが開かない場合は、配布サイトに表示される `index.json` のURLを VCCの **Settings → Packages → Add Repository** に入力してください。

ZIPを直接受け取った場合は、プロジェクト外のフォルダーへ展開し、`package.json` のあるフォルダーを **Settings → Packages → User Packages → Add** から登録できます。この方法では新バージョンの自動取得はできません。

## オリジナルからの移行

本ツールは `yagihata.radialinventorysystem.v4` を置き換えます。オリジナルと同時に入れないでください。設定と生成アセットは従来の `Assets/YagihataItems/RadialInventorySystemV4/` を使用します。

**バックアップ付き移行（Windows・推奨）**

1. 配布されたVPMパッケージZIPを、対象プロジェクトの外へ展開します。
2. Unityでシーンを保存し、Unityを閉じます。
3. 展開先の `install.bat` をダブルクリックして、対象プロジェクトのフォルダーを選びます。
4. Assets・Packages・ProjectSettings・UserSettingsのコピーを作成した後、元のVPMパッケージを置き換えます。
5. Unityを開き、補助ツールから既存設定を読み込み、対象アバターと参照を確認します。必要に応じて「移行診断・参照の修正」で直してから適用してください。
6. 公開リポジトリをVCCへ登録しておけば、以降はVCCから更新できます。

VCCだけで置き換える場合も、先にVCCのプロジェクトバックアップを作成してください。`legacyPackages` により元のVPMパッケージを置き換えますが、本ツールのバックアップランチャーはVCCからの導入時に自動実行されません。

**.unitypackage版のスクリプトがAssets内にある場合**は、そのまま追加しないでください。クラス・GUIDが重複します。バックアップ後に旧コードを取り除き、設定JSON・生成アセット・画像を保持した状態で移行する必要があります。移行ランチャーは旧コードを検出すると処理を停止します。

## 更新と復元

- 公開リポジトリからの更新：Unityを保存して閉じ、プロジェクトのバックアップを作ってからVCCで更新します。Unityを開き、必要に応じて「適用する」でメニューを再生成します。
- ランチャーで更新：新しいZIPをプロジェクト外へ展開し、`install.bat` を実行します。
- ランチャーのバックアップはプロジェクトの親フォルダーの `RI-Kai-Backups` に保存されます。Assets全体のコピーに必要な空き容量を確保してください。
- ランチャーの復元：Unityを閉じ、展開先の `restore.bat` を実行。対象プロジェクトと `backup.json` のあるバックアップを選びます。復元直前の状態も保存します。
- VCCで作ったバックアップは、VCC側の手順で復元してください。ランチャー用のバックアップとは形式が異なります。
